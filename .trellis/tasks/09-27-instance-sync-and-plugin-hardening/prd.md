# 实例数据一致性与插件加固

## Goal

父任务：把「插件产包 → 脚本搬运 → 各实例一致」做成可重跑闭环（含备份），并修复插件已知缺陷

## 背景（承接上一轮）

上一轮 `09-26-all-instance-data-sync-e2e`（已归档）完成了**一次性重灌**：六个实例形态的数据同源、
E2E 基础设施（guard 17 / smoke 36 / matrix 122）入库、PT 通道打通。它留下两条**未闭环**：

1. **同步是一次性的、整包式的**：`scripts/instance-sync/` 走「整包重新灌入」，
   数据产生走的是**宿主原生端点**（`POST /api/users/backup`）而非插件本体；
   每次同步都要重灌全量（Luker 7178 条目 / PT 337 s）。
2. **插件自身缺陷已取证但未修**：R-16（转换路径断点续传不可达）、R-17（`npm run gen-fixtures`
   因入口守卫 URL 拼接缺陷**从未生效**）、R-19（`restoreCapability` 三态不可观测）。

本轮把这两条收口。

## Requirements

### PR-1 共享契约（两个子任务都必须遵守）

1. **产包口径契约**：插件在源实例产出的包，必须能与**宿主原生备份**做**条目级口径比对**，
   并产出差异读数。**不可达条目必须显式列出并从分母剔除**（沿用上一轮做法：宁可显式剔除，不得静默算作已覆盖）。
2. **搬运契约**：灌入目标**只走宿主原生通道**，**不裸拷贝文件**；写入语义一律 `merge`
   （覆盖同名、**绝不删除目标独有内容**，含空目录 —— 见上一轮 C-4 / R-9）。
3. **实例版本前置（R-20 纪律）**：凡用实例页面验证插件行为，**必须先把该实例的插件更新到与工作区同版本**
   （Dev 实例走 `git pull`，`origin` 已确认指向本仓、非上游）。未更新即验证 = 验证的是历史代码。
4. **只连 Dev**：E2E 一律只连白名单端口 `{8001, 8003, 8899}`，Real 端口出现即启动期抛错
   （`e2e/lib/guard.cjs` 已有实现，17 项负例用例）。
5. **零凭据入库 / 产物不入库**：产物（包、备份、快照）一律落 `Downloads/` 或
   `.trellis/tasks/**/research/`（后者不入版本库）；`test-results/` 由 `.gitignore` 管理。

### PR-2 集成验收（父级职责）

1. 两个子任务的 Acceptance Criteria **全部达成**，且各自有独立读数证据。
2. 五个可写目标（Dev ST / Real ST / Dev Luker / Real Luker / PT web）与真源**一致**：
   逐目标给出覆盖率与「零删除」证据；PT 沿用上一轮的模块读数判据（路径比对在 PT 上不可用）。
3. 插件产包通道**可重跑**：同一源实例**连续两次**产包，条目数与体积一致（证明确定性）。
4. 本轮全部新增/更正的规范落 `.trellis/spec/`（**自包含**，内联读数与 `file:line`，不得写「详见任务目录」）。
5. **环境收尾**：只关闭本次启动的实例；取证时已在运行的 `:8003` / `:8004` **保持原样**。

## Constraints

- **C-1 写入纪律（已不再是「偏离」）**：本轮要向实例目录写入 —— 但用户 2026-09-27 裁定
  「**所有实例可任意更改，但不动源码**」，`L0-1` 随之改写为 **v1.5.0「实例边界（数据可写 · 源码禁改 ·
  链接禁穿）」**（真源 `tavern-harness` `dabdbbf`，14 目标零漂移，10 仓已推送）。
  ⇒ 实例**数据**写入属规则**明确允许**面，**无须逐任务请批**。
  纪律保持：只走宿主原生通道、`merge` 语义（不删独有）、写入前只读快照、逐目标核对零删除、
  真实数据目标先备份。**另须守**：宿主源码禁改、**不得写穿**指向工作区仓的链接（`P-19`）。
- **C-2 真源内容只读**：Real Luker 的**内容**只被读；它作为写入目标时，写的是"从它自己导出的数据
  经他处转回"，**不得由其它实例的内容覆盖它**（它永远是源，不是被同步方）。
  其**插件目录**按子任务 A 的 U-5 更新（代码安装，非数据写入）。
- **C-3 TT 不纳入自动化**：TT 是 Tauri 桌面应用（无浏览器端口）⇒ 仍为**人工交付物**
  （TT 布局包 + 导入说明），不纳入本轮 E2E 与自动同步。
- **C-4 不引新依赖、不加构建步骤**（L1-MR-11 / 上轮 R4.1-4.2）：不新增 npm 包（含 `chokidar` —— U-2 已排除常驻监听），不改 `src/vendor/**`。
- **C-5 不改其他仓**：`Instance/**` 只被启动/调用；其他 My-repo 仓不被修改。
- **C-6 不改四个宿主源码**。

- 不清理 `Dev/Luker/.../extensions/third-party/` 空目录（上轮 R-9；须另走 PARDON）。
