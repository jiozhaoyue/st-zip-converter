# 一站式工作台原生化：UI 精简、性能止血与 Luker 原生对接

## Goal

把 st-zip-converter 从「功能堆叠的独立工作台」收敛为**一站式、简洁、高性能、原生贴合 Luker 的酒馆扩展**：
用户进入插件后能一眼看懂「能做什么」，主路径零学习成本，宿主零负担（不卡顿、不污染 UI），
且与 Luker 原生能力（存储配额、备份管理、扩展管理）无缝衔接而非各说各话。

## Background

### 用户需求（2026-09-25 原话要点）

> 需要查看当前插件状态，目前仍存在许多问题：
> ① UI 导致的 Luker 整体卡顿；② 功能按钮存在冗余，并不是酒馆原生风格；③ 加了过多特效；
> ④ 没有对接 Luker 原生的附加功能（如存储配额），还有数据包上下传、打包优化等。
> 一定要使插件是一站式，同时功能简洁明了，性能高。

补充裁定（同日交互问答）：

- **UI 改造方向**：**原地精简 + 原生化**（不改架构骨架，去特效应酬、砍冗余、收敛为宿主原生控件）；
- **范围**：四项全做——UI 精简与去特效、性能实测与止血、Luker 原生能力对接、上下传与打包优化；
- **任务结构**：父任务 + 子任务拆分；
- **逐项确认要求**：「怎么砍、怎么解耦复用按钮、以及对接 Luker 原生功能，都需要给出建议，一个一个看」——
  **任何删改与对接项都必须先出建议清单经用户逐项确认，不得批量自作主张**。
- **测试实例授权**：用户明确授权对 **8004 Real Luker** 做实测（「我让你做 real 就做，不要把数据搞坏就是约束」）——
  取代默认的 Dev 白名单口径，但**「不搞坏数据」是不可让渡的硬约束**。
