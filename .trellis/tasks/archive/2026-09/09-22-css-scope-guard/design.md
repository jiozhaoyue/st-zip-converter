# CSS 作用域守卫设计

## 边界

- `style.css` 是独立页面和宿主插件共用的输入。守卫只读取文件并报告错误，不改写 CSS。
- 独立的 Node 校验模块解析 CSS，遍历普通规则并检查每条逗号分隔的选择器；CLI 和 Vitest 调用同一函数。
- 解析选择使用 PostCSS 8.5.26，并固定为显式 devDependency；用户已授权该环境变更。它只用于开发期 CSS 语法解析，不进入浏览器运行时。

## 校验语义

- 合法：选择器以 `.app-container` 或 `.st-converter-drawer-app` 为根（容器自身或后代）；现有独立页面规则 `body:has(> .app-container)` 单独允许。
- 非法：其余任何普通元素选择器，包括嵌套于 `@media`、`@supports` 中的裸选择器。检查逗号列表的每一个分支，而不是只检查第一个。
- `@keyframes` 及其帧规则跳过选择器前缀校验。语法错误应令校验失败，并报告文件位置。
- 不因选择器中间或末尾出现容器名就放行，例如 `body .app-container` 仍会影响宿主祖先。

## 现有 CSS 迁移

- 两个 `@media` 内原有裸类规则同步添加独立页面与插件容器前缀；其中 `body` 规则限定为独立页面骨架选择器。
- 不更改声明值、断点、DOM 模板或转换逻辑。用测试和构建验证静态行为；本任务不连接酒馆实例。

## 风险与回退

- 嵌套规则和逗号列表容易被按行 grep 漏检，使用 CSS 语法树并以负例测试验证。
- 响应式规则原先泄漏到宿主的效果可能曾被误当作插件样式；修复时需确认两种容器都覆盖原目标。
- 回退范围仅为本任务的校验脚本、测试、npm script 与响应式选择器，不触碰已有未提交变更。
