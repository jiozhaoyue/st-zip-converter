# 8004 实测诊断与性能止血

> 父任务：`09-25-workbench-native-onesop`（一站式工作台原生化）
> 本子任务持**取证**职责：其结论是 T2（UI 精简）/ T3（原生对接）/ T4（上下传收敛）的输入。

## Goal

在用户授权的 **8004 Real Luker** 上做严格只读的实机取证，回答三个问题：

1. **插件是否真的是 Luker 卡顿的来源？**（复核 09-07「与插件无关」的旧结论是否仍成立）
2. **若是，卡在哪里？**——点名到具体文件:行号或具体 DOM/CSS 证据，不停留在「UI 导致的」这类笼统判断。
3. **能止血到什么程度？**——给出可执行方案与预期收益，交用户裁决是否实施。

## Background

- 用户体感：「UI 导致的 Luker 整体卡顿」。
- 旧证（`09-07`，当时版本）：拉取时整页卡**是插件责任且已修**（rAF 合帧后 longtask 14 → 2）；
  抽屉开合 12s CPU 采样无差异（scriptMs 22 vs 21），当时判定「打开抽屉持续卡」与插件无关，
  归因于页面上 43 个第三方扩展的持续 CSS 动画。
- **旧结论基于老版本，且当时的插件 CSS 与注入点已有变动（现 `style.css` 2620 行 / 27 处 transition / 4 个注入点 + MutationObserver 自愈），必须重新取证。**
- 环境：仅 8004 在跑；8004 **无登录门槛**（匿名 `/api/users/me` 返回 admin），插件已 Git 安装于 HEAD `355fdc1`。

## Requirements

| 编号 | 要求 |
| --- | --- |
| R1 | **只读取证**：仅使用 GET 与具只读语义的查询端点；**禁止** `POST /api/users/restore`、`extensions/{install,delete}`、任何转换/导出/删除/落盘动作、任何对 `Instance/**` 的写入。 |
| R2 | **工具**：全局 Playwright 1.62.1（`npx --no-install`，**不安装任何包**）；诊断脚本落 `research/`（规划路径，不入 `src/`）。 |
| R3 | **采样维度**（至少覆盖）：① LongTask（`PerformanceObserver`）；② 主线程 CPU（CDP `Performance.getMetrics` 的 `ScriptDuration`/`TaskDuration` 差值）；③ DOM 规模与样式表规则数；④ 抽屉关闭 vs 展开的**对照**采样；⑤ 插件注入节点的计算样式与布局盒（必要时用 `fe-ui-inspect` 手法）；⑥ 事件监听器规模与 `MutationObserver` 触发频次。 |
| R4 | **归因隔离**：区分「插件自身开销」「宿主重渲染/其他扩展开销」「传输期开销」三类，给出各自占比证据；不得把第三方扩展的开销记在插件账上，也不得反过来为插件开脱。 |
| R5 | **产物**：`research/live-report.md` 落盘，含原始数据表 + 对照结论 + 点名定位 + 止血建议（含预期收益与风险）。 |
| R6 | **止血方案先出后做**：方案经用户逐项确认后才进入实施；实施若涉及 `src/**` 代码改动，须走父任务 G2/G7 流程（测试全绿 + 守卫通过）。 |
| R7 | **不装包、不建全局 MCP**：不注册 `chrome-devtools-mcp` 到全局配置；若确需 MCP 交互诊断，用项目级 `.mcp.json` 并先获授权。 |

## Acceptance Criteria

- [ ] `research/live-report.md` 落盘，含原始采样数据（非转述）、对照实验设计、结论与证据链。
- [ ] 卡顿归因**点名定位**：每个被判定为插件责任的项，必须给出文件:行号或 DOM/CSS 证据锚点；每个判定为「非插件责任」的项，必须给出排除证据（如第三方扩展的动画清单、宿主自身的采样）。
- [ ] 旧结论（09-07 两份报告）逐条复核，明确「仍成立 / 已失效 / 需修正」并给出本轮证据。
- [ ] 止血建议清单成型（含预期收益、改动面、风险与降级方式），交用户逐项裁决。
- [ ] `Instance/**` 无写入痕迹；本轮无任何包安装；8004 真实数据零改动。
