# 统一工作区与转换工作台 UI 重构

> 父任务：09-07-workstation-overhaul · 依赖：host-detect（宿主分支行为）、perf-overhaul（新管线 API）——两者完成后执行

## Goal

消除 UI 双轨与重复：工作区收敛为**一个**区域（单列表+来源标签），宿主导出与外部互转合并为**统一转换工作台**（一套控件、一套按钮），所有产物经**统一待导出区**出口，宿主类目与工作区存储用量可视化列表化。

## Requirements

### R1 工作区单一区域（单列表 + 来源标签）
- 删除"IndexedDB 工作区：暂存 N 个数据包"状态条与"工作区数据包管理"抽屉的信息重复：状态条仅保留一句汇总 + 打开抽屉入口。
- 唯一工作区抽屉：顶部用量看板 + 统一列表。每个条目来源徽标：`上传` / `宿主导出` / `转换生成` / `增量补丁`（分卷以组关联）。
- 来源筛选（全部/按来源），跨条目统一操作：载入为转换任务 / 下载 / 删除 / 写回宿主（宿主可用时）。
- IndexedDB 数据模型扩展：`origin` 枚举（upload/host-export/converted/delta/split-part）+ `group`（分卷组/增量链）+ DB_VERSION 1→2 迁移（旧 role 映射，不丢数据）。

### R2 统一转换工作台
- 数据源二选一：宿主实时拉取（插件环境）或工作区任意选中包。
- 一套控件全源共用：类目勾选（含预设与联动）、目标格式、文件名模板（占位符芯片）、压缩率、分卷、扩展模式、增量基准、备份聊天过滤。
- ST 宿主特殊分支（来自 host-detect）：selection 由插件内过滤生效，UI 标注；Luker 透传。
- 删除原"宿主酒馆数据导出"独立区块与"外部数据包互转"独立区块的重复控件——两个区块合并为一个统一工作台。

### R3 统一待导出区
- 所有产物（宿主直出、转换产物、增量补丁、分卷）先进待导出区（内存队列 + preferences 持久化 id，不重复存 Blob）。
- 待导出区统一操作：逐条/批量 下载 / 存入工作区 / 写回宿主 / 移除。
- 原"导出并立即下载/导出并存工作区"双按钮路径收敛为：产物入待导出区 → 用户统一处置（保留"完成后自动下载"快捷勾选以兼容习惯）。

### R4 可视化看板（列表化）
- 工作区用量：IndexedDB 配额条（used/quota）+ 各包体积列表（名字/大小/来源/时间）。
- 宿主类目统计：Luker 走 selection 预检或拉回后 inspect；ST 拉全量后 inspect；显示各类目文件数+体积。入口放工作区抽屉顶部，数据源为当前选中包或宿主拉取包。

### R5 解耦复用与代码质量
- index.js（1192 行）拆分：统一工作台 controller、工作区 controller、待导出区 controller；事件绑定不混在单文件。
- category-filter 抽为共用组件（统一工作台内宿主源/工作区源同用）；archive-manager 重构为单列表组件。
- 100% 原生 `.inline-drawer` 体系、Font Awesome 图标、0 Emoji、touch ≥44px、无横向溢出——既有规范全部保持。

### R6 测试
- 单测：db 迁移（role→origin）、待导出区队列逻辑、来源筛选。
- Playwright 端到端：上传→转换→待导出→下载；宿主拉取→待导出→写回宿主；分卷组展示；用量看板渲染。

## Acceptance Criteria

- [ ] 界面上只有一个工作区数据包区域，状态条不再重复展示；单列表 + 来源徽标 + 筛选可用。
- [ ] 宿主导出与外部互转不再有各自独立的重复控件区；一套控件两类数据源均可完成完整流程。
- [ ] 所有导出动作最终经待导出区完成；批量操作可用。
- [ ] 用量看板显示配额与包列表；宿主类目统计可视化（插件环境）。
- [ ] 旧工作区数据升级无损（DB_VERSION 2 迁移后列表完整）。
- [ ] `npm test` 全绿、`npm run build` 无报错、Playwright 端到端通过。
- [ ] 提交并推送到 origin/main。

## Constraints

- 依赖子任务 host-detect、perf-overhaul 先完成归档；其 API/语义变化（platform 修正、zipIo 并发语义）作为本任务输入。
- 不引入新框架/依赖（原生 DOM + 现有 vendor）。
