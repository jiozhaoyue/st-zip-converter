# 转换路径真增量续传（跨会话保留半成品）

## Goal

把「暂停 → 续传后产物缺条目」这条**静默数据损失**缺陷改成**真增量续传**：续传时把已完成的半成品**原样搬运**进新包，再继续转换剩余条目 ⇒ 产物完整，且已做过的压缩工作不重做。

## 背景

### 缺陷现状（2026-09-28 现场取证）

| 事实 | 证据 |
| --- | --- |
| 转换路径的断点按 **crc 清单跳过**条目 | `src/core/transform.js:364-371`：命中 `resumeCrcMap` 即 `entry.skip()` |
| 目标 zip 每次都是**新建空包** | `src/core/transform.js:307` `await io.createWriter(targetPath, …)` |
| ⇒ 被跳过的条目**既不在旧产物（已丢）、也不在新产物（被跳过）** | 实测 1500 条聊天 → 1437 条（`e2e/standalone/specs/pause-resume.e2e.cjs:124-156` 的 `KNOWN-DEFECT`） |
| 旧产物为何丢了 | 暂停走 `worker.terminate()`（`src/core/worker-client.js:137`），`BlobWriter` 半成品随 worker 一起消失 |
| 规格早已承诺半成品保留 | `src/core/task-manager.js:6` 注释「暂停 = checkpoint 落盘 → abort → state=paused，**半成品保留待续传**」——**转换路径上这是假事实**（宿主拉取路径才成立） |
| 该路径此前不可达，**R-16 接线后才可达** | 子任务 `09-27-plugin-defect-fixes` §3 把 `btnConvert` 接进 `TaskManager` ⇒ 缺陷从「不可达」变成「用户点得到」 |

**为什么既有测试没抓到**：单测 `test/convert-resume.test.js:68` 锁的是**机理**（`not.toContain`「跳过的条目不在产物里」——把缺陷当契约钉住了）；E2E 只验证「日志出现跳过 N 项」。**没有一条断言问过「产物完不完整」**。

### 技术前提（已实测，不靠读 minified 代码推断）

zip.js 2.9.0 的 `ZipWriter#appendZip(reader)` 能把一个已有 zip 的条目**原样搬运**进新 writer：

- **字节级保持**：`compressedSize` / `compressionMethod` / `crc32` 逐条相等 ⇒ 零重压缩（实测读数见 `research/appendzip-probe.json`）；
- 搬运后**可以继续 `add`**，新条目接在半成品之后，顺序 = 「半成品在前」；
- 必须传 `zip.BlobReader` 实例（裸 `Blob` / `Uint8Array` 抛 `TypeError`）；
- **不回传条目名清单**；
- 截断/损坏的半成品会抛 `File format is not recognized`（可捕获）。

## Requirements

### R1 跳过的**充分条件**必须是「输出里真有这条」（MUST）

- 判据从「crc 命中清单」升级为「**crc 命中清单 且 目标包已含该条目**」；
- 任一条件不成立 ⇒ **不得跳过**（照常写出）⇒ 产物完整；
- 由此得到一条**结构性不变量**：*跳过 ≠ 丢数据*。任何未来调用方「只传 crc 清单、不传半成品」时，行为退化为**完整重做**而不是**静默残缺**。

### R2 真增量：半成品跨会话保留并原样续写（MUST）

- 暂停时把已写入的部分**收尾成一个合法 zip**（`close()`），从 worker 取出并持久化到 OPFS（`fetch-tmp/<taskId>.partial.zip`，复用既有 `opfsTmpHandle`）；
- 续传时用 `appendZip` 把它搬进新 writer，**不重压缩**，然后从断点继续；
- 源包与半成品必须**同源**（见 R4），否则作废半成品从零重做。

### R3 暂停语义改为「协作式收尾 + 有界兜底」（MUST）

- 暂停不再立即 `worker.terminate()`，而是先向 worker 发收尾信号、等它 `close()` 并回报半成品；
- **有界等待**（`L1-MR-7`）：超时即回落为「终止 + 无半成品」；
- 两条路径都必须守住：**回报半成品 ⇒ 续传可增量**；**未回报 ⇒ 续传完整重做**。两者都不得产出残缺包；
- `terminate()` 后**必须**置空 `workerInstance`（`L1-MR-8`，`src/core/worker-client.js:140` 既有实现不得回归）。

### R4 续传前必须校验「半成品与当前源包同源」（MUST）

- 校验：半成品里的条目集合 ⊆ 源包条目集合，且**同名条目 crc32 全等**；
- 不成立 ⇒ **作废半成品**（清理 OPFS 临时文件 + 清断点）+ `logger.warn` + 可操作提示，从零重做；
- 理由（实测踩点）：`appendZip` 之后 `writer.add` 对**已存在的名字是静默忽略**（探针负例：抛 `File already exists` 者仅限 `appendZip` 内部重复；`written` 集合去重路径会让重写变成空操作）⇒ 若源已变而仍续传，产物会**混入陈旧条目**且不报错。

### R5 半成品不可用时的降级（`L0-11` / `L1-MR-1`）（MUST）

- OPFS 不可用 / 半成品读取失败 / 协作式收尾超时 ⇒ 一律降级为「**不构成任何跳过**」（完整重做），**绝不阻塞主路径、绝不报失败**；
- 降级必须**显式可观测**（日志一行 + 任务控制条文案提到「将重做整包」），不得静默。

### R6 批量路径同源受益（MUST）

- 批量路径**子项内**暂停同样是「新空包 + 按 crc 跳过」⇒ 同一缺陷；
- R1 的充分条件落地后，批量路径**立即变为安全**（无半成品 ⇒ 该子项完整重做）；
- 批量侧的真增量（**每子项各自持久化半成品**）列为 R6b，与单包共用同一套机制。

### R7 非目标（MUST NOT）

- **不**改 `src/vendor/**`（`L1-MR-11`，只用既有 API）；
- **不**改 `src/core/plan-preview.js` / `delta.js` / `splitter.js` 的既有语义；
- **不**修 `test/real-samples.test.js` 的满载超时抖动（既有残留）；
- **不**碰实例目录、不碰其他仓（U-4）；
- **不**改「宿主拉取」路径已成立的 OPFS + Range 续拉实现（它是正确的，只作参照）。

## Constraints

- **C-1** 不引新依赖、不加构建步骤（`L1-MR-11`）。
- **C-2** `src/core/**` 保持**无 DOM 依赖**（OPFS 访问只在 `src/ui/` 与 worker 的浏览器分支）。
- **C-3** 既有对外契约不得破坏：`convert()` 中止时**仍抛 `AbortError`**（暂停态由 `TaskManager` 表达）；`runConversionTask` 成功时的返回形状不变。
- **C-4** 半成品属**临时物**，一律落 OPFS `fetch-tmp/`（或 Node 临时目录），**不入库、不入版本库**；任务完成/中止时清理（复用既有 `opfsTmpCleanup`）。
- **C-5** 每个新增/变更的判据都必须有**判别力证明**（改坏 ⇒ 转红 ⇒ 恢复 ⇒ 绿），读数落 `research/`。

## Out of Scope

- 宿主拉取路径的续传实现（已正确，不改）。
- 跨会话续传的**加密/校验和分级**（半成品完整性只做「能否被 appendZip 读出」这一层）。
- 「暂停 → 关闭页面 → 重开后续传」的 UI 引导文案打磨（R2 已让它技术上成立；文案属后续）。
